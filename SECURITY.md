# Security Policy

PromptWall is a security tool. We take reports of bypasses, vulnerabilities, and
weaknesses seriously, and we ask that you report them responsibly.

## Reporting a vulnerability

**Please do not open a public GitHub issue for security vulnerabilities**, including:

- A way to bypass the Input Firewall's injection detection
- A way to bypass or circumvent the Policy Engine's enforcement
- A way to tamper with the audit ledger without breaking the hash chain
- Any other issue that could let a malicious actor act outside the boundaries
  PromptWall is supposed to enforce

Instead, please report it privately by emailing **security@[your-domain-or-email]**
with:

- A description of the vulnerability and its potential impact
- Steps to reproduce it (a minimal example is ideal)
- Any suggested fix, if you have one

You can expect an initial response within 5 business days.

## Supported versions

While the project is in pre-1.0 development, only the latest released version on
`main` is supported with security fixes. Once a 1.0 release is published, a
supported-version table will be added here.

## Disclosure process

1. You report the issue privately.
2. We confirm and assess severity.
3. We develop and test a fix.
4. We release the fix and credit the reporter (unless you prefer to remain
   anonymous).
5. After a reasonable patch-adoption window, we may publish a short advisory
   describing the issue.

Thank you for helping keep PromptWall and the people who rely on it safe.
